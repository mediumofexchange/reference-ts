## The exhaustion circuits

The six circuits of §4.3 are generated by `scripts/venue/exhaustion-sources.mjs` into `src/exhaustion-circuits/` over
`exhaustion.nr` (state, digests, start and end conditions), `blake2b.nr` and the vendored sponge. Each check carries
a name, and the names below are the circuits' own. The argument assumes collision resistance of Blake2b-256's
compression and of `H` (pool-v2 §1's sponge), knowledge soundness of the backend's recursive verification with a
key bound to its key hash (bb 5.2.0, read in the decision above), and the BN254 scalar field's size, `p ≈ 2^254`.

### What a fold establishes

A reader takes a fold under §4.3 rules 1–4. The claim is §4.3's: the blocks from the start's child through the end
header form one chain; each block's transactions are exactly those whose ids reproduce its header's transactions
root, in order; `mapRoot` is the map at the end header (§4.2).

1. **The proofs form one run of leaves.** A fold verifies its period's tree under a key whose hash is a leaf's or the
   node's (`tree key`), with `NODE_KEY_HASH` as the third public input. A node verifies each child under a leaf's key
   hash or its own third input (`child key`) and passes that input on, so by induction every proof below a fold is a
   genuine leaf or node proof under the constants the fold holds; a tree under a made-up circuit cannot carry the
   genuine node key hash as its input. A node's children join at `middle`, so the leaves form one sequence of state
   hashes `s_0 → … → s_n`, `s_0` and `s_n` the fold's two state hashes. Each leaf advances one stream (`T`, `M` or
   `U`) and carries the other two unchanged in both of its state hashes.
2. **States are bound.** `state_hash` is `H` under `T_EX_STATE` over every field of the three streams: 64-bit words
   packed three to an element (below `2^192`), booleans as 0 or 1, the stack's 20 entries, every chain and the root.
   The encoding is injective, so each state hash names one state.
3. **Periods chain from the adopted start.** A first fold requires its start state to be a period's start
   (`assert_start`: nothing open, the stack empty, the next position zero, both streams at one height, every chain
   zero) at the header its public inputs name (`start id`, `start height`) with the empty map (`empty map`). A next
   fold requires the same of its start and verifies the previous fold under the first fold's key or `foldKeyHash`
   (`previous fold key`) with the same start and `foldKeyHash` and with its end, height and map root equal to this
   period's start. The reader pins `foldKeyHash` and the start (rules 2–3), so by induction the folds chain from the
   adopted start. Every fold requires its end to be a period's end (`assert_end`) and publishes the end header's id,
   height and the map's root (`end id`, `end height`, `map root`).
4. **The streams agree at each period's end:** both id chains equal (`period end: id chains`), the entry list's chain
   equal to the map's entry stream (`period end: entry chains`), the heights equal, no transaction or header open and
   the stack empty. Each chain is an `H` chain from zero, so equal chains mean equal sequences.

The three streams then give the three claims.

### The tree-and-header stream (`leaf-m`)

Each slot is at most one of: an id, a witness id, a merge, a lift, a header chunk (`one operation`); one Blake2b
compression a slot, over at most 128 bytes, zero past its length (`byte past a slot`).

- **Tree preimages are distinct by construction.** An id is pushed as `0x00 || id` (33 bytes, `id length`, `leaf
  prefix`), a witness id as `0x00 ||` 31 bytes (32 bytes, `witness id length`), a merge hashes `0x01 || below || top`
  (65 bytes, `merge length`, `node prefix`, `merged entries`), a lift `0x01 || top` (33 bytes, `lift length`,
  `lifted entry`). These are venue-ergo §4's leaves, nodes and lone children, and no preimage of one kind is one of
  another: prefixes differ between leaves and nodes, lengths between the two leaves and the two nodes.
- **The stack holds this block's subtrees.** Positions 0 and 1 are sentinels: a push writes at `sp + 2`, a merge at
  `sp` and needs `sp ≥ 2` (`merge into a sentinel`; `sp = 0` fails the index), a lift at `sp + 1` and needs `sp ≥ 1`
  (`lift over an empty stack`), so a sentinel is never read or written. A header's end resets `sp` to zero, so every
  live entry was written by this block's operations and is the root of a subtree of this block's pushes, in push
  order.
- **The root is the header's.** A header's first chunk requires exactly one live entry (`one root`) equal to bytes
  65–97 (`transactions root`) and bytes 1–33 equal to the last header's id (`parent id`); no tree step runs inside a
  header (`tree inside a header`). Every version lays these bytes out alike (venue-ergo §3: version, parent id,
  AD-proofs root, transactions root). By Blake2b's collision resistance and the distinct preimages, a stack root
  equal to a real header's root is that block's real tree, so the pushed ids are exactly the section's ids in order,
  under whichever of §4's rules the block uses.
- **Headers chain.** Chunks are full but the last (`short header chunk`, `empty header chunk`), so a header's id is
  standard Blake2b-256 of its bytes, kept as `m.prev` at its last chunk. Heights are counted, not read: `m.height`
  rises by one at each header's end. The fold's end id is on the reader's chain at the end height (rule 4), the start
  is pinned (rule 3), and each header names the last as its parent, so by collision resistance the headers proved are
  the reader's chain's from the start's child through the end, one height apart.
- **Each id joins the id chain** with its labels: the height of the block whose header follows and its position, which
  counts ids (not witness ids) from zero and resets at each header.

The empty section has no root this machine reaches; an Ergo block always carries its emission transaction.

### The transaction stream (`leaf-t`)

- **Slots spell transactions.** A slot starts or ends a transaction only if used (`start on an unused slot`, `end on
  an unused slot`), starts one exactly where none is open (`start inside a transaction`, `slot outside a
  transaction`), is full unless it ends one (`short slot`) and is zero past its length; a block starts only with a
  transaction (`block start`). The compression starts from Blake2b-256's initial state at a transaction's first slot,
  counts the bytes so far and sets the final flag at its last, so each finished transaction's digest is standard
  Blake2b-256 of its bytes, its id. A transaction may span leaves: its chaining value, count and scan registers are
  in the state.
- **The transactions are the blocks'.** Each id joins the id chain with its labels: the height rises at each block
  start and the position resets there and counts transactions otherwise. With both id chains equal at the period's
  end, the sequence of (id, height, position) is the tree stream's, so by collision resistance each transaction's
  bytes are the unsigned bytes of the transaction at that height and position, and every transaction of every
  block is read. The position at a period's start is not constrained; the first label must be (start + 1, 0) to
  equal the tree stream's, which forces a block start and resets it.
- **The scan runs from its start state at each transaction's first byte** over every byte (the reset in the leaf),
  with `src/ergo-scan.ts`'s tables generated into the leaf: one key per byte from the mode, the byte's class and five
  zero tests, an affine update of every register, and an emission where an output ends at a byte of the transaction
  (`A_OEND` times the slot's mask) with the shape register at 2. Bytes past a transaction's end are zeros under a
  zero mask: they change only registers the next transaction's start resets. Each entry carries its subject's two
  limbs, its height, position and output index.
- **The list is the emitted sequence.** Each listed entry has limbs below `2^128`, labels typed u32, and listed
  entries form a prefix (`list prefix`) in strictly increasing `(height, position, output)` (the range check on the
  difference, below `2^96`). The emitted and listed entries, each encoded `hi + δ(lo + δ·place)`, are compared as
  products of `γ − x` (`list`), with `γ` and `δ` hashed from the leaf's two state hashes, which bind every byte it
  hashed (through the ids and the open chaining value) and the list (through its chain). A prover fixes both before
  learning the challenges; distinct multisets pass with probability below `(EL + 4·EL²)/p < 2^-232` an attempt
  (`EL` = 668 entries a leaf; the second term bounds two encodings colliding), negligible against any number of
  attempts a prover can make. Emissions occur in
  byte order, which is `(height, position, output)` order, so the sorted list is the emitted sequence and the entry
  list's chain is the chain of the period's emitted entries in §4.2's order.

### The scan reads the grammar as the framer does

Venue-ergo §5 fixes the grammar and §6 the shape. Inside the grammar every VLQ is minimal and bounded, so a VLQ's
value is its integer and no register wraps; the scan's modes read it field by field:

| Grammar (venue-ergo §5) | Modes |
|---|---|
| Inputs: a count, then per input a 32-byte box id, a zero proof length, an extension count of at most 127 and its entries, each a key byte and a `Coll[Byte]` | `V_IN` (count to `C1`), `S_BOX` (32 bytes by `R`), `PROOF` (only `0x00`), `EXTCNT` (0, or 1–127 to `C2`), `E_KEY`, `E_CT` (only `0x0e`), `E_CLEN`, `E_BODY` (its length by `R`) |
| Data inputs and token ids: a count and that many 32-byte ids | `V_DI`, `S_DI`; `V_TOK`, `S_TOK` (32 × count bytes by `R`) |
| Outputs: a count; per output a value, a tree, a creation height, a token count with its tokens' index and amount, a register count of at most 6 and that many `Coll[Byte]` | `V_OUT` (count to `C1`), `V_VALUE`, `TREE`, `V_TSIZE` and `S_TBODY` (a sized tree), `PAT_P2PK` (35 more bytes), `PAT_FEE` (104 more), `V_HEIGHT`, `TOKCNT`, `V_TIDX`, `V_TAMT`, `REGCNT` (0, or 1–6 to `C2`), `R4_*`, `R5_*`, `RX_*` |
| Nothing after the last output | `END`: any byte goes to `ERR` |

A tree's first byte picks its kind as §5 does (bit 3 set and bits 5–7 clear: sized; `0x00`: pay-to-public-key;
`0x10`: the fee tree), and the scan skips each fixed tree's exact length without reading its bytes; inside the grammar
they are §5's. An output ends (`OEND`) at its register count where it has none, else at the last byte of its last
register, and the output counter `C1` ends the outputs at the count. **The shape:** `REGCNT` resets the shape register;
`R4` of length exactly 32 reads its bytes into the subject's limbs (`R4_HI`, `R4_LO`, 16 bytes each) and sets it to 1;
any `R5` that follows doubles it to 2; other registers keep it. So an output emits exactly where its own `R4` is a
32-byte `Coll[Byte]` and its own `R5` a `Coll[Byte]`: §6's shape. Inside the grammar the scan therefore reads exactly
the framer's shaped outputs, in output order, with their subjects. Outside it, the scan reads by its own deterministic
rule, which the set identity fixes (§4.2): it checks no bound or minimality, wraps a long VLQ in the field as the
circuit does (`scanStep` computes modulo `p`), and a byte its mode cannot take sends it to `ERR`, which it never
leaves. The [corpus](VENUE_ALTERNATIVES.md#the-agreement-corpus-slice-43) holds both readings equal over three days
and 65 crafted transactions.

### The map stream (`leaf-u`)

Each used slot (`update prefix`) takes the next entry, appends it to the entry stream, and replaces its key's leaf:
the key is the subject's low limb modulo `2^32` (`key`: `lo = q·2^32 + key` with `q` below `2^96`, unique because the
transaction leaves range-check `lo` below `2^128` and the stream equals their list), the old leaf is zero for a
count of zero with a zero chain (`empty leaf`) or `H(T_MAP_LEAF, c, chain)`, and the 32 siblings must take it to the
current root (`map path`), bit `l` of the key placing it as the right child at level `l` (§4.2). The new leaf is
`H(T_MAP_LEAF, c + 1, H(T_ENTRY, chain, entry))`. By collision resistance the old leaf is the key's true leaf, so
each update is §4.2's append and the root stays the map's. With the entry stream equal to the transaction leaves'
list at the period's end, the period applies exactly its emitted entries in order, and its end root is the map at
its end header from the root at its start: the adopted start's empty map, or the previous fold's root.

### What an honest prover can always prove

Soundness needs nothing below; a bound that failed would stop provers, not mislead readers.

- **A leaf's list holds every emission.** An emission needs, after its output's `REGCNT` byte, an `R4` type and
  length byte, 32 subject bytes and an `R5` type and length: at least 37 bytes between two emissions, so at most four
  end in a 128-byte slot, the list's `LIST_PER_SLOT`.
- **The stack holds every section.** 18 live entries take a tree of up to 2^17 leaves. Ergo's voted block cost
  (8,001,091 at height 1,895,424, against 2,407 an input, and every transaction spends one) admits about
  3,300 transactions a block, 6,600 leaves.
- **Labels fit 32 bits.** Heights are below 2^31 (venue-ergo §3); positions and output indices are below the block's
  byte size.

### Evidence and limits

`check:exhaustion` executes every named check above against a hostile witness otherwise consistent with the state
hashes, at small sizes from the same sources, and `--shipped` runs the same set over the shipped full-size programs
with the pinned nargo, with real headers of versions 1 to 4 (`test/fixtures/ergo-mainnet-version-blocks.json`)
honest and with their parent or root altered ([report](ergo-exhaustion-check-verification.json)). The recursive
joins are proved in `exhaustion-prove.mjs` with five hostile recursions
([measurements](VENUE_ALTERNATIVES.md#the-exhaustion-circuits-in-production-form-slice-43)). Limits: execution
checks no recursive verification; the order check is a range check without a message; mainnet holds no output with
the shape, so the map-update leaves run on synthetic entries until testnet days are recorded (local).
